## 1. 总目标

在现有静态逆向成果上，完成宠舍管家 `2.15.0 (73)` 的全量证据化逆向，补齐运行态页面、真实字段、请求/响应、权限、会员门禁、状态守卫、通知联动、经营模块与 Web 平台行为，并将每一项能力映射为熊舍管家的“保留、改造、替换、后置或不采用”决策。

本轮不是重新摘录已有报告，而是把现有报告中的“推断、待动态确认、字段待确认”逐项关闭，形成可复跑、可追溯、可直接生成研发任务的完整对标基线。

## 3. 完成定义

本轮只有同时满足以下条件才算完成：

1. `205` 条页面路径全部进入页面目录，标记为独立页面、弹窗、组件、Binding、废弃入口或权限入口。
2. `32` 个 Controller、`66` 个 Service、`87` 个 Entity 全部建立职责、依赖、字段与调用证据。
3. `250` 条 App API 与 `231` 条 Web API 全部完成去重、分组、来源和状态标注。
4. P0 核心链路全部具有“入口 → 页面 → 字段 → 请求 → 状态变化 → 后续副作用 → 错误路径”的闭环证据。
5. docs/01 至 docs/04 中每一个“推断、待确认、待动态确认”均被标记为“已验证”或“受阻并记录原因与补证条件”。
6. 每个逆向结论都能追溯到二进制、运行截图、运行日志、请求样本、公开前端或 App Store 证据之一。
7. 敏感值全部脱敏；证据目录不保存令牌、Cookie、手机号、用户业务数据或生产凭据。
8. 形成熊舍管家逐功能差距矩阵和可直接进入开发的任务清单。
9. 验证脚本、证据哈希、文档交叉引用和既有 `make ci` 全部通过。

## 4. 证据等级

所有条目必须使用以下等级，禁止把推断写成事实：

| 级别 | 含义 | 典型证据 |
|---|---|---|
| S | 静态已验证 | AOT 字符串、源码路径、类名、方法名、资源、Info.plist |
| D | 动态已验证 | 真机/模拟器截图、交互录像、控制台日志、网络请求 |
| W | Web 已验证 | 管理端/编辑器第一方 JavaScript、公开页面和路由 |
| P | 公开资料已验证 | App Store 截图、产品说明、版本历史 |
| I | 高可信推断 | 两类以上证据可互相印证，但缺少运行态闭环 |
| B | 受阻 | 已记录阻断、已尝试路径、所需补证条件 |

## 11. 风险与处理

| 风险 | 处理方式 |
|---|---|
| 目标版本启动受阻 | 保留 B 记录；并行使用 AOT、公开 Web、App Store、运行日志和已有动态报告补证 |
| 页面受账号/会员限制 | 记录拦截页面、权益键和入口条件；不把未进入页面写成已验证 |
| 请求字段仅在运行时生成 | 结合 DTO 字符串、表单字段、Service 调用和合成夹具请求交叉确认 |
| API 版本变化 | 固定 2.15.0 基线；新版本另做差异清单 |
| Web 资源哈希变化 | 每次采集保存 URL、时间、文件和 SHA-256，不覆盖旧版本 |
| 静态推断过度 | 所有推断保留 I 标签，只有运行或直接结构证据才升级为 D/S/W |
| 证据泄露敏感值 | 采集后先脱敏再入库，验证脚本扫描 token、cookie、手机号和密钥模式 |
| 逆向结论与熊舍实现混杂 | docs/09-12 只描述目标事实；docs/13 单独承载熊舍决策 |
