# 熊舍管家 MVP 产品与技术设计

> 日期：2026-07-16  
> 状态：设计已由用户授权主 Agent 定稿  
> 来源：docs/01 至 docs/04、当前会话确认项与 Figma Phase 0 调研

## 1. 产品目标

熊舍管家面向中国大陆个人及专业仓鼠繁育者，首版以单舍主账号完成“建档—笼位—配对—分笼—孕期—产仔—窝仔—断奶—分性分笼—个体化—归档”的可信数据闭环。

首版成功标准：

1. 用户可在一个账号下管理仓鼠、窝次、笼盒、任务、媒体和公开分享。
2. 任何配对、分笼、产仔、数量调整和个体化操作均由服务端动作接口校验。
3. 产仔数量、当前在养数量、临时幼崽身份和正式个体档案自动对账。
4. 用户可通过 CSV 导入已有资料，并随时导出或备份自己的数据。
5. 系统可统计账号名下活跃个体、媒体空间等用量，为后续计费保留稳定挂点。

## 2. 技术基线

- 客户端：Flutter，iOS 与 Android 同一代码库。
- 服务端：模块化单体 REST API。
- 主数据：PostgreSQL。
- 异步任务：PostgreSQL Outbox 与任务表，不引入 Redis。
- 媒体：S3 兼容对象存储、CDN、图片派生和短视频转码 Worker。
- 登录：手机号验证码。
- 市场与语言：中国大陆、简体中文、默认 Asia/Shanghai。
- 离线：只读缓存与本地草稿；业务提交需在线完成。

## 3. MVP 范围

### 3.1 纳入

1. 单舍主账号与个人熊舍。
2. 仓鼠单只建档、同窝批量建档与 CSV 导入。
3. 笼架、笼盒、入住、移笼、隔离与清洁历史。
4. 配对计划、配对观察、强制分笼和孕期窗口。
5. 产仔、窝次、临时幼崽、数量流水、断奶、分性分笼与个体化。
6. 克级体重、健康快捷记录、任务、日历和本地通知。
7. 家谱图、共同祖先与基础近亲提示。
8. 图片、短视频、图片编辑、封面与媒体时间线。
9. 可撤销公开链接，用于分享仓鼠或窝次卡片。
10. 显性数据中心：CSV 导入、导出、基础备份、用量概览。
11. 物种规则模板、舍主复制调整和历史规则快照。

### 3.2 后置

- 多成员与角色权限。
- 客户、预订、交付、合同、财务与库存。
- 遗传模拟、AI、小程序、公开社区、评论、关注与直播。
- 蓝牙秤、温湿度传感器和跨熊舍协作。

## 4. 信息架构

首版固定五导航：

1. 今日：紧急事项、今日任务、预产与窝仔节点、异常体重、待清洁和快捷记录。
2. 仓鼠：个体、窝次、搜索、筛选、建档、体重健康与家谱图。
3. 笼舍：笼架网格、笼盒详情、入住、移笼、隔离和清洁。
4. 繁育：待配对、配对中、孕期、窝仔、待个体化和归档。
5. 我的：熊舍资料、物种规则、媒体分享和显性数据中心。

数据中心在“我的”首页直接展示，并在“今日”提供备份状态入口，不埋入二级设置。

## 5. 账号隔离与计量

1. 所有租户业务表均包含 owner_id。
2. 所有唯一约束优先采用 owner_id 与业务键的组合。
3. API 从认证上下文解析 owner_id，不接受客户端替其他账号提交 owner_id。
4. 系统字典采用 scope=system 且 owner_id 为空；舍主复制后形成 owner_id 非空的版本。
5. 账号用量至少统计 active_hamsters、active_litters、enclosures、media_bytes、video_minutes 和 backup_bytes。
6. 首版不展示付费墙，但保留 entitlement、usage_meter 和 usage_snapshot 数据结构及只读接口。

## 6. 谱系图模型

谱系不以 hamster 表上的 father_id 与 mother_id 作为唯一事实源。

核心关系：

- pedigree_parentage：父母个体到子代个体的有向边，包含角色、证据、置信度和有效期。
- litter_parent：父母个体与窝次的关系。
- litter_member：窝次与临时幼崽或正式个体的成员关系。
- relationship_assertion：导入或人工补录的待验证关系。

同窝关系由 litter_member 推导；父母关系既可从窝次父母推导，也可记录直接断言。未来遗传模拟读取统一关系图，不迁移既有 father_id 与 mother_id 字段。

## 7. 产仔、数量与个体化闭环

1. confirm-birth 动作幂等创建一个有效窝次、初始数量事件和 N 条 pup_identity。
2. pup_identity 是独立监护身份，可记录编号、性别置信度、体重、表型和状态，但不是正式 hamster 档案。
3. 后补发现、死亡、转出和纠错均追加 litter_count_event，并同步新增或关闭对应临时身份。
4. sex-and-separate 动作批量提交性别与笼位，服务端验证容量、异性混笼、待复核和版本号。
5. individualize 动作原子地把所有符合条件的 pup_identity 一对一转换为 hamster，建立 litter_member 与 pedigree_parentage。
6. 完成前必须满足：
   - 初始活仔数 + 后补发现数 - 死亡数 - 转出数 = 当前应管理数；
   - 当前应管理数 = 未个体化存活身份数 + 已个体化正式档案数；
   - 无待复核性别、无缺失笼位、无未处理数量异常。

## 8. 导入、导出与备份

### 8.1 CSV 导入

首版支持仓鼠、笼盒和体重三类模板；仓鼠模板可通过父母编号和窝次编号导入谱系关系。

流程：上传文件 → 编码与列识别 → 字段映射 → 全量预检 → 冲突预览 → 正式导入 → 错误报告。

导入采用 import_job、import_row 和 import_issue；正式写入使用幂等批次号，部分失败时输出逐行结果，不静默丢弃父母、窝次或笼位引用。

### 8.2 导出与备份

- 数据中心直接展示最近备份时间、备份大小和可恢复状态。
- 支持仓鼠、笼舍、繁育、窝次、体重、健康和谱系的 CSV/JSON 导出。
- 基础备份包含结构化数据、媒体清单和校验哈希。
- 导出与备份采用异步任务，提供进度、失败原因、重试和过期时间。

## 9. 媒体与公开分享

1. media_asset 保存原始文件事实；media_variant 保存缩略图、转码、封面和编辑派生。
2. 图片编辑首版包含裁剪、旋转、滤镜和标注；保存编辑配方及派生文件，不覆盖原图。
3. 短视频支持上传、封面、转码、播放状态和失败重试。
4. share_page 使用随机公开令牌，可设置过期时间并随时撤销。
5. 公开页只展示舍主显式选择的字段和媒体，不包含内部健康备注、联系方式和审计事件。

## 10. API 规则

- 资源读取使用标准 REST。
- 状态迁移使用动作接口，客户端不直接 PATCH state。
- 所有写入支持 Idempotency-Key。
- 可并发编辑资源使用 version 乐观锁。
- 批处理返回逐项结果与统一事务结果。
- 错误统一包含 code、message、field_errors、current_version 和 recovery_actions。
- 分页采用 cursor；时间统一传输 UTC，并返回计算所用 timezone。

## 11. Figma 低保真原型

正式交付为 Figma 可点击原型，不交付 HTML。

Figma Starter 计划采用三页结构，以 Section 分组而非拆成大量 Canvas Page：

- 00 · 基础与组件：封面、使用说明、Foundations 与本地低保真组件。
- 01 · MVP 主页面：初始化 4 屏、今日 3 屏、仓鼠 5 屏、笼舍 3 屏、繁育 9 屏、我的与数据 4 屏。
- 02 · 动作面板与流程：12 个动作面板，以及主流程、异常路径和原型连线说明。

12 个动作面板为：快捷记录、编辑建档、批量建档、媒体编辑、入住移笼、清洁隔离、近亲检查、配对观察、分笼、数量/称重、断奶分性、分享预览。

低保真采用 Noto Sans SC、单模式灰阶变量和少量状态色，目标是验证信息层级、动作闭环和错误恢复，不追求品牌视觉。

## 12. 验收与错误处理

1. 现有文档 02 的 15 个繁育验收案例全部映射到 PRD、Schema 与 OpenAPI。
2. CSV 导入至少覆盖缺列、重复编号、父母缺失、循环谱系、笼位冲突和非法体重。
3. 生产确认、分笼和个体化具备幂等、并发冲突与恢复路径。
4. 通知关闭不影响站内任务。
5. 媒体转码、公开分享和导出失败不回滚业务事实。
6. Figma 页面无文本裁切、重叠、断链和缺失返回路径。

## 13. 排期基线

团队：1 名 Flutter、1 名后端、0.5 名产品/UI、0.5 名测试，双周迭代。

建议 8 个迭代、16 周：

1. 基础工程、登录、账号隔离与规则。
2. 仓鼠、笼舍与 CSV 导入。
3. 配对、分笼与孕期。
4. 产仔、窝次、数量流水与临时幼崽。
5. 断奶、分性分笼、个体化与家谱图。
6. 体重健康、任务日历与通知。
7. 媒体、编辑、分享、数据中心与计量。
8. 导出备份、全链路测试、灰度与发布。
