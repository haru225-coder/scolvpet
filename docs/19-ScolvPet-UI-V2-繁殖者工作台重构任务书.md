# ScolvPet UI V2 · 繁殖者工作台重构任务书

日期：2026-07-20  
目标版本：`0.0.4`（UI V2）  
任务性质：**表现层与交互层重构**，不是业务架构升级，不是“自由美化一轮”

---

## 0. 本轮结论先冻结

产品定位：

> **面向金丝熊专业繁殖者的管理 SaaS。**

不是普通养宠 App，不做纯可爱化；也不是冷冰冰 ERP。

目标视觉：

> **Warm Professional Breeding SaaS**  
> 专业数据 × 金丝熊行业语言 × 暖色品牌 × 少量蜡笔手绘资产

已批准视觉稿作为 **方向参考 / moodboard**，不是要求逐像素照抄。

本轮允许大幅调整：

- 信息架构
- 页面布局
- 导航
- UI component
- Design Token
- 图标
- 插画与空状态资产

但：

> **只重构表现层和交互层，不借 UI 重构升级业务架构。**

本轮最关键的三刀（优先于“换成暖色”）：

1. **5 → 3 导航收口**
2. **繁育从菜单变工作流**
3. **仓鼠详情从游戏 HUD 变专业个体档案**

## 2. 第一原则：先砍导航

当前：

```text
今日
仓鼠
管家
繁育
我的
```

必须从 **5 个底部一级 Tab** 收敛为：

```text
工作台        仓鼠        繁育
```

这是本轮最重要的信息架构调整之一。

### 2.1 今日 → 工作台

“今日”不再作为产品一级概念。

改成：

# 工作台

它解决的是：

> 繁殖者今天需要知道什么、处理什么、关注什么。

### 2.2 仓鼠

保留一级入口。

这是核心个体资产入口：

```text
个体档案
状态
品系
性别
年龄
血缘
笼盒
健康
繁育表现
后代
去向
记录
```

### 2.3 繁育

保留一级入口，并强化。

这是产品最核心的行业差异化：

```text
配对 → 交配 → 孕期 → 待产 → 产仔 → 窝次 → 育仔 → 分窝 → 留种 / 转出 / 交付
```

## 3. 砍掉「管家」一级 Tab，但不砍 AI

当前“问问管家”不能继续作为独立一级页面。

AI 改为：

> **全局上下文能力**

建议入口：

```text
工作台右上角：✦
仓鼠详情右上角：✦
窝次详情右上角：✦
```

AI 根据当前 context 工作。

例如仓鼠详情：

```text
✦ 关于「哈利 A02」

最近体重趋势如何？
是否适合安排繁育？
总结历史繁育表现
有没有值得关注的异常？
```

窝次：

```text
✦ 关于「L20260708-01」

幼崽发育情况如何？
什么时候适合分窝？
总结本窝记录
```

### 禁止

不要重新造：

```text
AIRepository
AIController
AIFeature 五件套
```

沿用现有能力，只调整入口与 UI。

## 6. P0：工作台重构

当前首页结构不要小修。重新组织信息层级。

### 6.1 Header

从：

```text
今日

龙之介                       正常
```

改为类似：

```text
工作台

下午好，龙之介                  🔔  [头像]
7月20日 · 周一
```

不要用巨大标题占据首屏。

### 6.2 第一优先级必须是「今日待办」

繁殖者打开 App 第一件事不是看统计数字，而是：

> 今天有什么必须处理？

设计：

```text
今日待办  4                         查看全部

┌────────────────────────────┐
│ 10:00                       │
│ A02 哈利 · 体重记录           │
│                     待完成 → │
├────────────────────────────┤
│ A07 × B03                   │
│ 孕期 Day 14 · 建议检查状态     │
│                        查看 → │
└────────────────────────────┘
```

状态至少统一：

```text
待完成
即将到期
逾期
需关注
已完成
```

### 6.3 第二层：经营概览

现在：

```text
在养
2只仓鼠

笼盒
活跃窝次
需关注
```

改为真正 dashboard：

```text
经营概览

在养       活跃窝次      孕期待产      需关注
24            6             3             2
```

原则：

- 同一层级。
- 不要四张厚重 Card。
- “需关注”可以强调。
- 其他数字保持中性。
- 数字可点击才做明显 interaction affordance。

### 6.4 第三层：繁育动态

必须加入。

例如：

```text
繁育动态

A03 × B07
孕期 Day 12
████████────
预计产期 7月27日
```

或：

```text
孕期 3 · 待产 2 · 育仔 4
```

然后列出最近 2–3 条重要繁育事件。

不要让用户必须进入“繁育”才能知道当前繁育状态。

### 6.5 首页插画使用规则

首页不做大面积 Hero 插画。

允许：

```text
一只小型手绘金丝熊
记录册
木屑
窝
小麦
```

作为：

- 空状态
- corner decoration
- 小品牌锚点

占视觉比例控制在约 **10–20%**。

## 7. P0：仓鼠列表重构

现在列表信息不足。繁殖者需要“一眼识别”。

### 7.1 Header

```text
仓鼠                           ＋

搜索编号 / 名称 / 血统 / 品系
```

不要顶部放多个无明确意义的小图片按钮。

### 7.2 Filters

现在五个大胶囊可以保留逻辑，但视觉减重。

例如：

```text
全部 24   在养 18   繁育中 4   转出 2
```

低频状态放「筛选」：

```text
退役
离世
性别
品系
出生区间
笼盒
```

不要一开始把所有状态全铺出来。

### 7.3 个体卡

设计目标：

```text
┌─────────────────────────────┐
│ [真实头像] 哈利            A02 │
│          ♂ 鸽灰波利 · 8月龄    │
│          父 A11 · 母 B04      │
│ ● 在养             笼盒 C-12 │
└─────────────────────────────┘
```

必须支持：

- media avatar 正常显示。
- 无真实头像时使用统一金丝熊 placeholder。
- 不再使用“哈”这种首字母 CRM avatar 作为正常视觉方案。

首字母只能作为最终错误 fallback。

## 8. P0：仓鼠详情彻底统一

当前详情页黑底 / 黄绿 HUD 与整个 App 不属于同一视觉体系。本轮直接重做 UI。

### 8.1 Header

```text
←                              ⋯

[头像]

哈利                           A02
♂ 鸽灰波利
金丝熊 · 8个月

● 在养         笼盒 C-12

[ 编辑档案 ]
```

背景回到暖白 / 奶油色。  
**禁止整页 Dark Dashboard。**

### 8.2 二级导航

```text
概览   繁育   健康   谱系   记录
```

不要把所有内容堆在一张超长页面里。

### 8.3 概览

```text
基本信息

出生日期       2025.11.12
性别           ♂
品系           鸽灰波利
毛色           鸽灰
体重           168 g
笼盒           C-12
```

### 8.4 繁育表现

核心 SaaS 数据：

```text
配对次数       4
成功窝次       3
后代数量       21
平均窝仔数     7.0
```

数据存在才显示。不能为了 UI 填假数。空数据走 empty state。

### 8.5 谱系

不要只做普通字段列表。

目标最终形成真正 pedigree UI：

```text
        祖父
    父
        祖母

      哈利

        外祖父
    母
        外祖母
```

第一轮不要求复杂图算法。先保证：

- 父母关系可读
- 祖代有数据时可以扩展
- 点击节点进入个体
- 不做新领域模型

## 10. P1：建立统一视觉系统

不要每个页面各写一套。

### 10.1 Color

方向参考：

```text
Background     暖白 / 奶油白
Primary        金丝熊暖橙
Text           深咖黑
Secondary Text 灰褐
Surface        白 / 浅奶油
Success        柔和绿
Warning        琥珀橙
Danger         克制的砖红
```

避免：大面积纯黑、高饱和荧光绿、随机粉色、每个模块一个颜色。

### 10.2 Typography

统一：

```text
Display
Page Title
Section Title
Card Title
Body
Secondary
Caption
Data Number
Button
```

中文不要因为“标题”就无节制使用超大粗体。

### 10.3 Radius

统一 3 档足够：

```text
small
medium
large
```

禁止 `12/14/16/18/20/22/24/28` 每处随便写。

### 10.4 Spacing

形成固定 rhythm。优先收敛：

```text
4 / 8 / 12 / 16 / 24 / 32
```

不要每个页面自己的 `13/17/21/27`。

## 12. P1：视觉资产补全

路径：

```text
assets/illustrations/
```

视觉统一为：

> 暖色、纸张颗粒、蜡笔/彩铅手绘感、克制、自然、不追求 AI 超精细。

主题只围绕：

```text
金丝熊 · 繁育记录册 · 窝 · 木屑 · 小麦 · 笼舍 · 幼崽 · 谱系 · 护理记录
```

### 第一批至少补

| 场景 | 内容 |
|---|---|
| 空任务 | 金丝熊安静趴在记录册旁 |
| 无仓鼠 | 小金丝熊从空档案册后探头 |
| 无繁育计划 | 两只金丝熊 + 尚未填写的繁育记录册 |
| 无窝次 | 温暖小窝、木屑、轻微脚印 |
| 无健康记录 | 金丝熊站在体重秤 / 小记录板旁 |
| AI 管家 | 金丝熊 + 打开的记录册 |

### 禁止生成

- 戴听诊器的 AI 医生仓鼠
- 3D Pixar 仓鼠
- 超写实摄影假图
- 大眼萌宠模板
- 满屏爱心
- 通用猫狗元素

## 13. P1：空状态统一

建立一个现有 UI 层可复用的 Empty State 表达即可。不要新建复杂架构。

结构：

```text
[插画]

还没有窝次记录

完成第一次产仔记录后，
这里会自动形成窝次档案。

[ 新建窝次 ]
```

所有 empty state 至少包含：

```text
图 · 标题 · 解释 · 下一步
```

不要只显示「暂无数据」。

## 14. P2：AI 管家重新接入

AI 不再一级 Tab。做全局入口后，根据 context 提供不同 suggestions。

工作台：

```text
今天有哪些需要处理？
有没有逾期任务？
哪些仓鼠需要关注？
繁育进度怎么样？
```

仓鼠详情：

```text
总结这个个体
分析繁育表现
查看健康风险信号
```

繁育：

```text
本周预计有哪些重要节点？
有哪些待产？
哪些窝需要准备分窝？
```

必须明确：

> AI 只读现有数据并辅助导航/总结。

不要因为 UI 重构引入新的数据修改路径。
