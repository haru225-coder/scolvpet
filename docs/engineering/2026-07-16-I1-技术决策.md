# I1 技术决策

## 已写入

- API 固定为 Go 1.26 模块化单体，HTTP 使用标准库，PostgreSQL 使用 `pgx/v5`，便于两人团队维护并保留清晰模块边界。
- 认证使用短期 HMAC Bearer 访问令牌与内存刷新会话；验证码使用可替换短信适配器，开发环境提供固定模拟码。正式短信供应商只通过接口和配置接入，不把凭据写入仓库。
- 写动作在数据库事务内完成：先校验 owner/幂等/版本，再写业务事实、`domain_event` 和 `outbox_message`。Worker 使用 PostgreSQL `FOR UPDATE SKIP LOCKED`，不引入 Redis。
- Web-01 为独立 Node SSR 工程，I1 仅提供健康检查和 `/s/:token` 边界页，不读取公开分享数据。
- 会话刷新已作为最小契约演进写入 OpenAPI `/v1/auth/sessions/refresh`，包含请求体、Idempotency-Key、SessionResponse 和统一错误响应；Flutter 只调用生成的 `DefaultApi.refreshSession`。
- Flutter 应用只通过生成目录中的 `dart-dio` 客户端访问 API；缓存仅保存最近成功壳层/账号/熊舍/规则，离线禁止业务写入。
- Flutter/Gradle 下载和构建均有显式超时：本地 Make 默认依赖获取/分析/测试 900 秒、Android 构建 1800 秒，Gradle HTTP/HTTPS 连接和读取 60000 毫秒；CI 另外设置 job/step 超时。
- OpenAPI Generator 7.23.0 生成后执行固定校正脚本，处理 generator 对 nullable `oneOf` 和布尔常量的 Dart 语法兼容，再由 `build_runner` 生成序列化辅助文件；校正不新增业务 DTO。
- 数据库迁移按源 Schema 的依赖顺序拆分，源 Schema 保持冻结；I1 只增加 `db/migrations/` 和系统规则种子。
