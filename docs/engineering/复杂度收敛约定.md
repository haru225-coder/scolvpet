# 复杂度收敛约定

状态：已写入（2026-07-20）。**现有代码不要求一次性整改；新代码必须遵守。**

本约定来自 ponytail-review 后的执行合同：诊断（Flutter 重复模型/仓储、Go 双架构）保留，处方收成「先砍重复与空转，不砍业务边界」。

## 执行原则

只删除**没有独立语义**的层。

| 优先删 | 默认留 |
|---|---|
| 纯转发、字段 1:1 映射、重复状态模板 | 事务 / 权限 / 不变量 / 跨资源编排 / 幂等 |
| 测试专用实现进入生产树（`lib/`） | 测试仍可写（mock 或 `test/` 旁 double） |
| 仅以「将来可能换实现」为理由的抽象 | 已有第二入口或第二实现后再抽 |

判断口令：

1. 删掉这一层后，业务规则是搬家还是消失？
2. 删掉后，事务 / 幂等 / 测试是否更难表达？

答不好就不动。

## API 单轨

> 新增 API 默认采用 `handler → store/SQL`。仅当存在跨资源事务、复杂业务不变量、幂等编排或多入口复用时，才引入独立 service / application 层。禁止仅为「分层完整」新建 `*core`。

说明：

- 现有 `i2core` / `i3core` / … 不要求立刻拆掉；**停止继续扩**。
- 新接口优先学 `p1_*`：在 `httpapi` 中校验权限与入参，经 `store` 或直接 SQL 完成读写。
- 需要 service 时写明理由（跨资源事务 / 不变量 / 多入口），不要默认复制 `*core` 模板。

## Flutter：DTO

新 feature **禁止**无业务语义的手写 DTO 镜像：

```text
GeneratedDto  →  FeatureModel  →  ViewModel   // 禁止空转
```

允许的中间模型必须增加业务语义（校验、展示派生、领域不变量），不能只是字段拷贝。

优先：

- 页面 / controller 直接使用 `scolvpet_api` 生成类型；
- 展示差异用 `extension`，不重写平行 `*models.dart` 字段表。

既有 `*models.dart` 不强制重写；**新代码与新字段不得再扩镜像层**。

## Flutter：Memory / Fake

- 测试专用 `Memory*` / Fake **不得**放在 `apps/mobile/lib/` 生产树。
- 放在 `apps/mobile/test/`（推荐 `test/support/`），或测试文件内私有 double。
- 生产路径上的可选适配器（如 SharedPreferences / 通知插件不可用时的内存后备）可以留在 `lib/`，但须有独立语义（「无插件时的本地后备」），不得借测试 double 之名堆第二套完整 Repository。

验收：`lib/` 中不再为「方便测试」维护第二套 `Memory*Repository`；测试仍然容易写。

## Flutter：AppServices

目标不是 Service Locator，而是把根组件构造参数爆炸收成显式依赖束：

```dart
// 期望
ScolvPetApp(services: AppServices(...))

// 避免继续增长
ScolvPetApp(
  authRepository: ...,
  petRepository: ...,
  crmRepository: ...,
  // 20+ 参数
)
```

依赖仍在 `main` 中显式构造并注入；`AppServices` 只是记录类型 / 参数对象。

## 执行顺序（冻结 → 清理 → 试点）

1. **冻结复杂度增长**：本文件 + `AGENTS.md`（本 commit）。
2. **清理明显重复**：Memory 出 `lib/`、`AppServices` 收束（下一步 commit）。
3. **纯机械拆文件**：大文件按屏/资源拆，不改业务行为。
4. **薄模块试点删层**：挑一个无复杂边界的模块验证「删接口」是否划算。
5. **再决定是否规模化**。

每步可独立回滚。迁移时发现旧代码很丑也**先别顺手修**。

## 第 1+2 步验收（不数行数）

| 项 | 通过标准 |
|---|---|
| DTO | 新 feature 无 `Gen → FeatureModel → ViewModel` 空转；中间模型必须带业务语义 |
| Memory | `lib/` 无测试专用第二套仓库；测试仍可写 |
| AppServices | 根组件依赖显式收束，不是隐藏式 Service Locator |
| API 单轨 | 新 PR 不新增仅为分层完整的 `*core` |

## 明确不做（本阶段）

- 不批量删除 repository 接口 / service 层
- 不强制页面全面改 `FutureBuilder`
- 不把 CSV 导入改成外部脚本
- 不替换自研 objectstore / 不删除 outbox

以上项需**逐用例**审查后再动。
