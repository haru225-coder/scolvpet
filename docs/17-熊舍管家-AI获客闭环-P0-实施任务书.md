## 1. 产品判断

熊舍管家的 AI 不应停留在“只读问答助手”。P0 要验证的核心价值是：

> 从真实仓鼠数据生成可拍摄内容，通过公开页面承接咨询，并把咨询沉淀为可追踪客户线索。

AI 是增长闭环的编排层：

```text
仓鼠/窝仔/媒体/健康事实
  → 内容机会
  → 视频或直播脚本
  → 专属获客链接
  → 公开主页咨询
  → 客户线索与来源归因
```

一级入口面向用户应命名为“获客”，而不是“AI”。AI 是实现方式，获客才是用户结果。

## 2. 本轮唯一主闭环

执行代理必须完整跑通下列场景：

1. 舍主从真实仓鼠中选择一只已设置公开资料的仓鼠；
2. 选择“短视频”或“直播”、平台、目标、时长和语气；
3. AI 基于实时结构化事实生成脚本、分镜、口播、字幕、标题和 CTA；
4. 脚本保存为一条获客活动，并生成唯一 `campaign_code`；
5. 用户可复制脚本、调用系统分享，并复制公开获客链接；
6. 访客打开 `/p/{slug}?campaign={campaign_code}`；
7. 访客查看公开熊舍与仓鼠信息，可向 AI 顾问提问；
8. AI 只依据已发布的仓鼠公开资料回答，并返回匹配建议；
9. 访客提交称呼及手机号或微信后，形成 CRM 线索；
10. 舍主在“获客”中看到线索来源、感兴趣仓鼠、咨询摘要与对应活动。

如果某一步未形成真实 API、持久化数据或可测试 UI，则闭环未完成。

## 5. 数据设计

新增迁移文件使用下一个可用编号。当前工作区已有未跟踪的 `0027_genetic_phenotype_feedback.sql`，本任务默认使用：

```text
db/migrations/0028_ai_growth_p0.sql
```

执行前再次确认编号未被占用。

### 5.1 `hamster_public_profile`

每只仓鼠的对外事实层。默认不公开。

建议字段：

```text
id uuid pk
owner_id uuid not null
organization_id uuid not null
hamster_id uuid not null
public_name varchar(160)
summary text
traits jsonb default []
filming_status varchar(24)  -- ready/rest/restricted
published boolean default false
consultable boolean default false
cta_text varchar(160)
price_label varchar(120) nullable
version integer
created_at / updated_at
```

约束：

- `(owner_id, hamster_id)` 唯一；
- 仓鼠、组织和资料必须同 owner；
- `consultable=true` 时必须 `published=true`；
- `filming_status` 只接受白名单值；
- 删除仓鼠后公开查询自动排除，不级联删除历史活动快照。

### 5.2 `growth_campaign`

视频或直播的获客活动，也是归因主键。

建议字段：

```text
id uuid pk
owner_id / organization_id
campaign_code varchar(24) unique
campaign_type varchar(16)   -- video/live
platform varchar(32)        -- douyin/xiaohongshu/wechat_channels/other
status varchar(16)          -- draft/ready/published/archived
subject_type varchar(16)    -- hamster/litter
subject_id uuid
title varchar(200)
goal text
duration_seconds integer nullable
tone varchar(80)
cta text
facts_snapshot jsonb
script_payload jsonb
model_name varchar(120)
prompt_version varchar(40)
published_at nullable
version integer
created_at / updated_at
```

`facts_snapshot` 必须保存生成时使用的公开事实和来源。旧脚本不得随仓鼠数据变化而静默改写。

### 5.3 `public_consultation` 与 `public_consultation_message`

用于公开页访客咨询和人工接管摘要。

核心字段：

```text
public_consultation:
  id, public_token_hash, token_prefix
  owner_id, public_site_id, campaign_id nullable
  interested_hamster_id nullable
  status open/lead_created/closed
  turn_count, started_at, last_message_at

public_consultation_message:
  id, consultation_id, role user/assistant
  content, facts_snapshot jsonb
  created_at
```

公开 token 使用随机值并只保存哈希，沿用公开分享 token 的做法。

### 5.4 `crm_contact_attribution`

不破坏既有 CRM 表，使用独立归因表：

```text
id uuid pk
owner_id
contact_id
campaign_id nullable
consultation_id nullable
source_channel varchar(32)
landing_path text
interest_hamster_id nullable
intent_summary text
metadata jsonb
created_at
```

一个联系人允许存在多个来源触点，但同一咨询只能生成一次首触归因。

## 6. AI 事实与输出约束

### 6.1 三种状态必须分离

仓鼠的内部状态、内容状态和商业状态不可混用：

- 内部状态：健康、体重、笼盒、繁育、备注；
- 内容状态：`filming_status`、公开媒体、是否适合出镜；
- 商业状态：`published`、`consultable`、是否已有有效预订。

AI 对外只能读取公开资料、允许公开的媒体和安全投影字段。

禁止对外暴露：

- `internal_code`；
- 当前笼盒位置；
- 内部 notes；
- 未公开健康明细；
- owner/account 标识；
- 未选择公开的媒体对象键；
- 其他客户信息。

### 6.2 脚本结构

生成结果必须为结构化 JSON，Go 与 Flutter 都使用明确模型，不以一整段 Markdown 作为唯一数据格式。

```json
{
  "title": "...",
  "hook": "...",
  "cover_text": "...",
  "sections": [
    {
      "order": 1,
      "duration_seconds": 3,
      "shot": "...",
      "voiceover": "...",
      "overlay": "..."
    }
  ],
  "caption": "...",
  "hashtags": ["..."],
  "cta": "...",
  "facts": [
    {"key": "birth_date", "value": "2026-...", "source": "hamster.birth_date"}
  ]
}
```

直播类型仍使用同一外层结构，但 `sections` 表示直播环节，并允许较长时长。

### 6.3 模型调用

- 抽象为 `growthcore.Generator` 接口；
- 必须提供确定性规则/模板实现，保证无 API Key 时功能和测试可运行；
- 可选 LLM 实现复用现有 OpenAI-compatible 调用方式；
- 优先读取 `AI_API_KEY/AI_BASE_URL/AI_MODEL`；
- 为既有部署兼容，可回退读取 `XAI_API_KEY/XAI_BASE_URL/XAI_MODEL`；
- LLM 只生成文案，不决定哪些事实可公开；
- 返回后校验结构、事实引用和长度，失败时自动退回模板结果；
- 保存 `model_name`、`prompt_version` 和事实快照。

### 6.4 公开 AI 顾问

公开 AI 顾问首期只处理：

- 当前有哪些可咨询仓鼠；
- 品种、性别、生日、公开特点和成长阶段；
- 根据新手/品种/性别/性格偏好进行匹配；
- 如何联系熊舍；
- 引导留下联系方式。

每一轮必须重新读取当前 `published=true AND consultable=true` 的资料，避免旧会话继续推荐已下架仓鼠。

返回结构：

```json
{
  "answer": "...",
  "session_token": "...",
  "recommendations": [
    {
      "hamster_id": "...",
      "public_name": "...",
      "summary": "...",
      "reason": "...",
      "media": []
    }
  ],
  "facts": [],
  "handoff_suggested": false
}
```

当用户进入价格协商、健康承诺、预订确认、订金或投诉场景时，`handoff_suggested=true`，回答引导人工联系。

## 7. API 契约

所有鉴权 API 位于 `/v1/growth/*`；公开 API 位于 `/v1/public/sites/{slug}/*`。

### 7.1 鉴权 API

```text
GET  /v1/growth/public-hamsters
PUT  /v1/growth/public-hamsters/{hamster_id}
GET  /v1/growth/opportunities
GET  /v1/growth/campaigns
POST /v1/growth/campaigns/generate
GET  /v1/growth/campaigns/{campaign_id}
POST /v1/growth/campaigns/{campaign_id}/publish
POST /v1/growth/campaigns/{campaign_id}/archive
GET  /v1/growth/leads
```

写接口遵循现有：

- `Idempotency-Key`；
- owner 隔离；
- 结构化错误；
- 乐观版本或状态守卫；
- 领域事件/审计方式与现有服务保持一致。

### 7.2 公开 API

```text
GET  /v1/public/sites/{slug}/catalog
POST /v1/public/sites/{slug}/consult
POST /v1/public/sites/{slug}/leads
```

公开接口要求：

- 公开主页必须已发布；
- `Cache-Control: no-store` 用于咨询和线索；
- 请求体有长度限制；
- 不回显内部标识或数据库错误；
- catalog 只返回已发布且有效的资料和公开媒体；
- lead 至少包含 `name`，并要求 `phone` 或 `wechat` 任一存在；
- campaign code 无效时仍允许成为自然流量，但不得伪造归因。

### 7.3 OpenAPI

更新 `specs/api/openapi.yaml`：

- 路径、请求、响应和错误模型完整；
- operationId 唯一；
- 示例使用中文业务数据；
- 公开接口明确 `security: []`；
- 更新生成 Dart 客户端并通过 drift 检查。

## 12. 验收案例

```text
熊舍：雪团熊舍
```
