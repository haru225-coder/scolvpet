# 熊舍管家 MVP 开发排期

> 文档版本：v1.1  
> 文档状态：DONE（复核修订后的 16 周执行基线）  
> 日期：2026-07-16  
> 周期：8 个双周迭代，共 16 周  
> 团队：2 人复合团队（成员 A：Flutter + 产品/UI；成员 B：后端/SSR + 测试/DevOps）  
> 需求基线：docs/05-熊舍管家-MVP-产品需求文档.md

## 1. 排期目标

在 16 周内交付 Flutter iOS/Android 熊舍管家 MVP，完成单舍主账号下的仓鼠、笼舍、繁育窝仔、体重健康、任务提醒、基础谱系、CSV 导入、图片与短视频、公开分享、数据中心、导出备份和账号用量闭环。

本排期以可演示、可测试和可发布为目标，不把后置能力提前塞入迭代：

- 不做多成员和 RBAC。
- 不做客户、财务、遗传模拟、AI、小程序和社区。
- 不设置付费墙。
- 离线只做缓存浏览和本地草稿。

### 2.3 分支与发布策略

1. 每个需求使用短生命周期功能分支，合并前完成代码评审和自动化测试。
2. API 契约和数据库迁移向后兼容；同一迭代内先发布兼容后端，再启用客户端入口。
3. iOS 与 Android 每个迭代至少生成一次可安装测试包。
4. 高风险动作使用服务端开关控制入口，但不改变已承诺 MVP 范围。
5. 第 8 迭代只接受发布阻断修复、性能、安全和合规变更。

## 3. 全局进入门与退出门

### 3.1 Definition of Ready

一个需求进入开发前必须具备：

1. 对应 PRD 编号、页面/动作面板和验收案例。
2. 页面信息层级、空态、加载态、错误态和恢复路径。
3. REST 路径、请求/响应、错误码、Idempotency-Key、version，以及 PRD 8.4 对应的动作迁移、守卫和重放结果约定。
4. 数据库实体、owner_id、唯一约束和事务边界。
5. 测试数据、正常链路、异常链路和跨账号隔离用例。
6. 外部依赖已可用，或已有明确模拟服务。

### 3.2 Definition of Done

一个需求完成必须同时满足：

1. Flutter iOS/Android 行为一致，主要返回路径可达。
2. 后端按 owner_id 隔离，动作接口不接受客户端直接提交目标状态或数量。
3. 单元、集成、契约和关键 Widget 测试通过。
4. 数据库迁移可重复执行，并有回滚或前向修复策略。
5. 错误码、日志、审计和恢复动作完整。
6. 产品/UI 和测试共同完成验收；无 P0/P1 缺陷。
7. 迭代演示物可在测试环境从头操作完成。

| 手工双端回归 | 通知权限、相册/相机、短视频、弱网、系统版本和商店包 |

### 15.2 缺陷等级

- P0：数据丢失、跨 owner 泄露、数量/谱系错误、主流程不可完成、严重崩溃。
- P1：核心功能错误但有临时规避、幂等/并发异常、导入/备份结果不可信。
- P2：非核心交互或显示问题，不影响事实正确性和主流程。
- P3：文案、轻微布局和优化建议。

任何迭代退出时 P0/P1 必须为零。
