## 1. 文档目的

本 PRD 定义熊舍管家 MVP 的产品范围、信息架构、页面与动作面板、领域流程、业务规则、异常恢复、验收案例和非功能要求，作为 Flutter、后端、产品/UI 和测试共同使用的单一研发基线。

本文中的状态、数量、账号隔离和数据一致性规则均以服务端为最终事实源。客户端负责采集输入、展示服务端投影和提供恢复入口，不自行推导繁育状态、窝仔数量或跨实体关系。

## 2. 产品背景与目标

### 2.1 目标用户

首版服务一个账号下的单舍主，覆盖个人繁育者和专业熊舍经营者的单人工作流。首版不提供多成员协作和 RBAC。

公开分享页的访问者是匿名只读访客，不属于熊舍账号体系，也没有任何业务写权限。

### 2.2 核心问题

1. 仓鼠繁育周期短，配对结束、分笼、孕期观察、断奶和分性节点密集，依赖人工记忆容易遗漏。
2. 新生阶段通常先按窝管理，过早建立正式个体档案会增加录入成本，过晚建档又容易丢失数量和谱系关系。
3. 仓鼠、笼盒、窝次、体重、健康、媒体和任务分散记录时，难以形成可审计的数据闭环。
4. 既有用户常持有表格资料，需要可靠的 CSV 导入、冲突预览和逐行错误报告。
5. 用户需要看见数据备份、导出和账号用量，而不是把数据管理入口埋入设置深层。

### 2.3 MVP 目标

1. 完成“建档—笼位—配对—分笼—孕期—产仔—窝仔—断奶—分性分笼—个体化—归档”的端到端闭环。
2. 所有关键业务动作由服务端校验，支持幂等、乐观锁、数量对账和可恢复错误。
3. 使用父母边、窝次和个体成员关系构建基础谱系图，并提供共同祖先与基础近亲提示。
4. 支持仓鼠、笼盒和体重 CSV 导入，支持结构化数据导出与基础备份。
5. 支持图片、短视频、图片编辑、媒体时间线和可撤销公开分享。
6. 显性展示数据中心和账号用量，为后续商业化保留稳定计量点，但首版不设置付费墙。

### 2.4 成功标准

1. AC-01 至 AC-26 全部通过，且无 P0/P1 级数据一致性缺陷。
2. 任意跨 owner_id 读取或写入均被服务端拒绝，自动化隔离测试全量通过。
3. confirm-birth 在单一事务中处理两种结果：N>0 时创建唯一窝次、初始数量事件和 N 条 pup_identity，并直接进入 litter_nursing；N=0 时进入 no_litter_outcome，且不创建 litter、litter_count_event 或 pup_identity。
4. individualize 在单一事务中将 N 条符合条件的 pup_identity 转为 N 条 hamster，并建立完整窝次成员和谱系父母边。
5. CSV 正式导入前完成全量预检，正式导入后每一行都有成功或错误结果。
6. 数据中心可直接查看最近备份、导出任务和六项用量指标。

## 3. 产品范围

### 3.1 MVP 纳入

1. 手机号验证码登录、单舍主账号和个人熊舍。
2. 五导航：今日、仓鼠、笼舍、繁育、我的。
3. 仓鼠单只建档、同窝批量建档、搜索筛选、生命周期和媒体时间线。
4. 笼架、层位、笼盒、入住、移笼、隔离和清洁历史。
5. 配对计划、近亲检查、配对观察、强制分笼、孕期窗口和异常挂起。
6. 产仔确认、窝次、数量流水、临时幼崽身份、断奶、分性分笼、个体化和归档。
7. 克级体重、幼崽掉重监护、健康快捷记录、任务日历和本地通知。
8. 父母边—窝次—个体成员构成的基础谱系图。
9. 仓鼠、笼盒和体重 CSV 导入。
10. 数据中心、CSV/JSON 导出、基础备份和完整性校验。
11. 图片、短视频、图片裁剪/旋转/滤镜/标注、封面和失败重试。
12. 仓鼠或窝次的可撤销公开分享链接。
13. active_hamsters、active_litters、enclosures、media_bytes、video_minutes、backup_bytes 用量计量。
14. 系统物种规则模板、舍主复制调整和历史计划规则快照。

### 3.2 明确后置

1. 多成员、邀请、角色权限和 RBAC。
2. 客户、预订、交付、合同、收据、财务和库存。
3. 遗传模拟、AI 助手和自然语言繁育建议。
4. 微信小程序、公开社区、评论、关注、直播和内容增长工具。
5. 蓝牙秤、温湿度传感器、Widget 和跨熊舍协作。
6. 付费墙、套餐拦截和超量阻断。

### 3.3 技术与运行边界

- 客户端使用 Flutter 单代码库交付 iOS 和 Android。
- 服务端采用模块化单体 REST API，主数据使用 PostgreSQL。
- 异步任务使用 PostgreSQL Outbox 与任务表；首版不依赖 Redis。
- 登录方式为中国大陆手机号验证码。
- 离线模式只提供已缓存数据浏览和本地草稿；业务提交、状态迁移、导入、分享、导出和备份均需在线完成。
- 媒体使用 S3 兼容对象存储、CDN、图片派生和短视频转码 Worker。

## 4. 用户与权限模型

### 4.1 舍主

舍主是首版唯一登录业务角色，可管理自己 owner_id 下的熊舍资料、规则、仓鼠、笼舍、繁育、窝次、任务、媒体、分享、导入、导出、备份和用量。首版为单舍主，不提供多成员 RBAC。

### 4.2 匿名公开访客

匿名访客仅能通过有效公开令牌读取舍主明确选择的仓鼠或窝次字段和媒体。访客无法搜索熊舍私有数据，也无法访问健康备注、联系方式、内部任务、审计事件或其他未选择字段。

### 4.3 账号隔离

1. 所有租户业务表必须包含 owner_id。
2. 所有熊舍内唯一约束使用 owner_id 与业务键的组合。
3. API 从认证上下文解析 owner_id，不接收客户端指定其他账号的 owner_id。
4. 任意读取、写入、导入、导出、媒体签名、分享创建和备份任务都必须带入认证 owner_id 范围。
5. 系统字典使用 scope=system 且 owner_id 为空；舍主复制后生成 owner_id 非空的私有版本。
6. 首版不存在成员列表、角色切换、协作指派和 RBAC 设置页面。

## 6. 十条端到端业务流程

### F01 登录与个人熊舍初始化

P01 手机号登录 → P02 验证码校验 → P03 创建个人熊舍 → 复制系统物种规则 → P04 选择手工建档或 CSV 迁移 → P05 今日总览。

### F02 CSV 初始化迁移

P27 上传 CSV → 编码与列识别 → 字段映射 → 全量预检 → 冲突预览 → 用户确认 → 正式导入 → 逐行结果与错误报告 → 进入仓鼠或笼舍列表。

### F03 今日任务闭环

P05 查看紧急与今日事项 → P06/P07 打开任务 → 完成、延期或添加业务记录 → 服务端关闭或重排提醒 → 今日卡片和关联实体刷新。

### F04 仓鼠档案生命周期

A02/A03 建档 → 关联来源、当前笼盒、媒体和关系 → P09 持续记录体重健康、繁育和笼位 → 状态变为退役、转出或死亡 → 保留历史和谱系。

### F05 笼盒入住、移笼、隔离和清洁

P13/P14 选择笼盒 → A05 入住或移笼 → 服务端校验同时段占用 → 写入 enclosure_stay → A06 隔离或清洁 → P15 保留完整历史。

### F06 配对计划、观察和强制分笼

P16 新建计划 → A07 近亲与资格检查 → 发布 → P18 开始配对 → A08 记录观察 → 正常结束或安全停止 → A09 同时提交双方去向 → 进入 P19。

### F07 孕期观察和产仔

P19 根据规则快照展示预产区间 → 记录体重和观察 → 修正基准时服务端重算提醒 → P20 confirm-birth：若 N>0，原子创建窝次、初始数量事件和 N 条 pup_identity，并直接进入 litter_nursing 后打开 P21；若 N=0，原子记录无活仔结果并进入终态 no_litter_outcome，不创建窝次或临时身份，转入 P24 结果摘要。

### F08 窝仔数量、体重和健康监护

P21/A10 按临时身份逐只称重 → 服务端比较上次和出生体重 → 生成掉重任务 → 后补发现、死亡、转出和纠错追加数量事件 → 数量账实时投影。

### F09 断奶、分性分笼和个体化

P22/A11 完成逐只断奶、分性和笼位预检 → 服务端 sex-and-separate → P23 请求服务端生成完整 eligible set、eligible_set_token 和 N 条正式档案预览 → individualize 提交 token 与逐只字段覆盖 → 服务端在事务内重新计算并校验 eligible set 后原子创建 N 条 hamster、litter_member 和 pedigree_parentage → 数量对账 → P24 完成归档。

### F10 媒体、分享、数据中心和备份

P09/P11 上传图片或短视频 → A04 图片编辑或等待视频转码 → A12 生成可撤销分享 → P25/P27 查看用量、导出和备份 → 今日 P05/P07 查看备份状态与失败恢复。

## 7. 详细功能需求

### 7.1 认证、账号和 owner_id 隔离

| 编号 | 需求 |
|---|---|
| ACC-01 | 支持中国大陆手机号验证码登录；验证码发送、校验、重发和频率限制由服务端处理。 |

### 7.4 繁育计划与状态机

计划主状态：

draft → pair_ready → pairing → post_pair → gestation → litter_nursing → weaning_due → sex_separation_due → individualizing → completed。

产仔结果分支：

- `confirm-birth(N>0)`：`gestation -> litter_nursing`，同一事务内完成产仔事实、唯一窝次、初始数量事件和 N 条临时身份；客户端看不到中间状态。
- `confirm-birth(N=0)`：`gestation -> no_litter_outcome`，记录实际产仔时间、其他结果数、原因和母鼠状态，不创建 litter、litter_count_event 或 pup_identity；`no_litter_outcome` 为可归档终态。

`birth_recorded` 在 MVP 中只作为 `BIRTH_CONFIRMED` 审计事件语义，不是可持久停留或可由客户端观察的计划状态。其他异常和终止状态为 hold、unsuccessful、cancelled。

| 编号 | 需求 |
|---|---|
| BRD-01 | 发布计划前校验父母不是同一个体、性别角色、生命周期、繁育资格、休养期、进行中计划冲突和共同祖先。 |
| BRD-02 | 每个计划保存 species_rule_version 快照；规则升级不改写历史计划。 |
| BRD-03 | 每次配对创建独立 pairing_attempt，不覆盖上一轮开始、结束、父本、观察和分笼信息。 |
| BRD-04 | 客户端不得 PATCH state；publish、start-pairing、separate、start-gestation、adjust-baseline、confirm-birth、wean、sex-and-separate、individualize 和 complete 使用动作接口，并遵守 8.4 的迁移—守卫—幂等矩阵。 |
| BRD-05 | 离开 pairing 前必须保存结束时间、实际分笼时间和双方无冲突的去向笼盒。 |
| BRD-06 | 攻击、受伤、强应激或分笼不完整进入 hold，并生成最高优先级分笼任务。 |
| BRD-07 | 结果可为有效、待定或未成；待定允许进入观察窗，但界面不得显示为医学确诊怀孕。 |
| BRD-08 | 超过预产区间只生成结果确认任务，不自动设置 unsuccessful。 |
| BRD-09 | 日期修正追加纠错事件并重算提醒；旧提醒标记 superseded。 |
| BRD-10 | 可并发编辑的计划、配对、窝次和笼位使用 version 乐观锁。 |

### 7.5 产仔、窝次、数量和个体化

| 编号 | 需求 |
|---|---|
| LIT-01 | confirm-birth 接收实际产仔时间、初始活仔数 N、其他结果数、母鼠状态、结果原因、Idempotency-Key 和当前 version；母带崽笼盒仅在 N>0 时必填。 |
| LIT-02 | N>0 时，confirm-birth 在一个数据库事务中记录生产事实，创建一个有效 litter、一条 delta=N 的 initial litter_count_event、N 条 pup_identity、父母与窝次关系及后续任务，并把计划从 gestation 直接迁移到 litter_nursing；任一步失败则整个事务回滚。 |
| LIT-03 | N=0 时，confirm-birth 在一个数据库事务中记录 `BIRTH_CONFIRMED_NO_LIVE_PUPS`、实际时间、其他结果数、结果原因和母鼠状态，并把计划从 gestation 迁移到 no_litter_outcome；该分支不得创建 litter、litter_count_event、pup_identity 或窝仔阶段任务。 |
| LIT-04 | 重复 confirm-birth 按原幂等键返回已提交分支的原始结果；N>0 返回已有窝次和临时身份，N=0 返回已有 no_litter_outcome，均不得重复创建事实。 |
| LIT-05 | pup_identity 是可独立称重、记录性别置信度、表型和状态的监护身份，不等同于正式 hamster。 |
| LIT-06 | 后补发现新增正向数量事件并补建身份；死亡、转出和纠错追加对应事件并同步身份状态。 |
| LIT-07 | 服务端根据数量流水计算 current_managed_count；客户端不计算状态或数量，只展示服务端结果。 |
| LIT-08 | sex-and-separate 批量提交逐只性别、置信度和笼位；服务端校验容量、异性混笼、待复核安排和 version。 |
| LIT-09 | P23 预览由服务端在同一 owner_id 与 litter version 下完整计算 eligible set：所有仍在管理、存活、未个体化的 pup_identity 必须已断奶、性别已确认、笼位有效、未处于阻塞异常；响应返回完整 identity 列表、不可篡改的 eligible_set_token/哈希和不合格原因。客户端不得删减、补充或自行判定 eligible set。 |
| LIT-10 | individualize 只接收 eligible_set_token、当前 version、按 identity 键控的允许字段覆盖和 Idempotency-Key。服务端在锁定事务中重新计算 eligible set，并与 token、覆盖键集合和当前应管理数逐项核对；集合变化、漏项、多项或新阻塞条件均整体拒绝并返回最新预览。MVP 不支持部分个体化提交。 |
| LIT-11 | eligible set 校验通过后，individualize 在一个数据库事务中把 N 条身份一对一转为 N 条 hamster，回填映射，创建正式 litter_member 和 pedigree_parentage；任一编号、谱系或笼位写入失败则整体回滚。 |
| LIT-12 | complete 前必须满足数量闭合、无待复核性别、无缺失笼位、无未处理数量异常、无阻塞任务，且所有当前应管理身份均已由本次或历史有效 individualize 形成正式档案。 |

数量闭合公式：

初始活仔数 + 后补发现数 - 死亡数 - 已转出数 = 当前应管理数

当前应管理数 = 未个体化存活身份数 + 已个体化正式档案数

上述数量公式只适用于 N>0 的 litter 分支；N=0 的 no_litter_outcome 不生成数量账，也不进入断奶、分性或个体化流程。

### 7.9 CSV 导入

首版提供仓鼠、笼盒和体重三类模板。仓鼠模板支持通过内部编号、父母编号和窝次编号导入基础谱系。

固定流程：

1. 上传：选择 CSV，创建 import_job，计算文件哈希和幂等批次号。
2. 列识别：识别编码、分隔符、表头和候选字段。
3. 字段映射：用户确认源列到目标字段，保存映射方案。
4. 全量预检：解析全部行，不只抽样；检查必填、类型、枚举、重复编号、父母缺失、循环谱系、窝次引用、笼位冲突和非法体重。
5. 冲突预览：按新增、更新候选、阻塞错误和警告分组展示。
6. 正式导入：用户确认后提交；服务端按 owner_id 和批次号执行。
7. 逐行错误报告：每个 import_row 返回成功、跳过或失败；import_issue 包含行号、列名、错误码、原值和修复建议。

历史窝次与父母关系按以下规则处理：

1. 仓鼠模板中的 `litter_code` 在 owner_id 内作为历史窝次业务键；预检先按 `litter_code` 分组，再解析该组的出生日期、父本编号和母本编号。
2. 数据库中不存在该 `litter_code`，且组内出生日期与已提供的父母事实一致时，正式导入自动创建一个 `origin=import`、`state=closed` 的历史窝次，并建立 litter_parent、litter_member 和 pedigree_parentage；历史窝次默认不生成断奶、分性、个体化或其他当前任务，也不计入 active_litters。
3. 同一历史窝次组内所有非空 `born_at`、`sire_code`、`dam_code` 必须一致；已提供的父母编号可来自同批次其他行或账号内已有仓鼠，且必须满足 owner_id、父母不同个体、性别角色和无循环祖先校验。未知父母允许留空，但不得在同组中一部分留空、一部分填写互相冲突的编号。任一冲突阻塞整个窝次组，不允许只导入部分同窝成员。
4. 数据库已有同编号窝次且出生日期、父母一致时，可在预览确认后追加尚未存在的成员；任一核心事实不一致时返回 `LITTER_FACT_CONFLICT`，不得通过普通 CSV 覆盖，需走谱系/出生事实纠错流程。

冲突与覆盖采用固定策略：

| 数据情形 | 默认结果 | 可选处理 |
|---|---|---|
| CSV 为空、现有字段非空 | 保留现有值 | 不提供空值覆盖 |
| CSV 非空、现有字段为空 | 更新候选 | 用户在冲突预览中按字段类别确认后补全 |
| 昵称、标签、备注等非核心字段均非空且不同 | 冲突候选，默认保留现值 | 用户显式选择本批次覆盖；决定记录在 import_job |
| internal_code、owner_id、出生窝次、父母关系、出生日期等核心事实冲突 | 阻塞错误 | 通过独立纠错流程处理，不在 CSV 导入中覆盖 |
| 同一批次重复 internal_code 或同窝组事实不一致 | 阻塞整组 | 修复源文件后创建新批次 |
| 完全相同记录或已成功导入行重放 | 幂等跳过 | 返回原行结果，不重复写入 |

| 编号 | 需求 |
|---|---|
| IMP-01 | 正式导入前必须完成全量预检；有阻塞错误时禁止提交。 |
| IMP-02 | 正式导入不静默丢弃父母、窝次、笼位或体重引用。 |

## 8. API、事务与错误规则

### 8.1 通用 API 规则

1. 资源读取使用 REST；状态迁移使用动作接口。
2. 所有写请求支持 Idempotency-Key。
3. 可并发编辑资源使用 version 和 If-Match 语义。
4. 列表使用 cursor 分页。
5. 时间以 UTC 传输，同时返回业务计算 timezone。
6. 错误统一返回 code、message、field_errors、current_version 和 recovery_actions。
7. 批处理同时返回事务总体结果和逐项结果。
8. owner_id 只从认证上下文获取。

### 8.2 服务端最终事实

以下结果只由服务端计算并返回：

- breeding_plan、litter、enclosure 的目标状态；
- 当前窝仔管理数量及数量差额；
- pup_identity 与 hamster 的转换数量；
- 谱系边和同窝成员关系；
- 笼盒占用冲突与容量结果；
- 提醒的生成、关闭、superseded 和去重结果；
- 用量指标。

客户端不得通过本地计算覆盖这些结果。

### 8.3 恢复动作

常见恢复动作包括刷新最新版本、选择其他笼盒、补录双方去向、修正日期、修正 CSV 行、补录数量事件、复核性别、重试媒体转码、重新生成下载地址和重试备份任务。

### 8.4 动作接口—状态迁移—守卫—幂等矩阵

所有动作均从认证上下文获取 owner_id，并在同一事务内校验 `If-Match/version`、状态守卫和资源归属。幂等键唯一域为 `owner_id + action_code + resource_id + Idempotency-Key`：相同键与相同规范化载荷返回首次结果，相同键但载荷不同返回 `IDEMPOTENCY_PAYLOAD_MISMATCH`；幂等结果至少保留 24 小时，confirm-birth、individualize 和分享撤销保留至对应业务记录归档。

| 动作接口 | 状态迁移/事实结果 | 核心服务端守卫 | 幂等结果 |
|---|---|---|---|
| `POST /v1/breeding-plans/{id}/publish` | `draft -> pair_ready` | 父母不同个体、角色与生命周期有效、规则快照存在、无进行中冲突、近亲结果已确认 | 重放返回同一计划版本和资格快照 |
| `POST /v1/breeding-plans/{id}/start-pairing` | `pair_ready -> pairing` | 配对笼可用、双方当前笼位明确、无其他有效配对、时间合法 | 重放返回同一 pairing_attempt |
| `POST /v1/pairing-attempts/{id}/separate` | `pairing/hold -> post_pair` | 结束时间合法、双方去向齐全、笼位容量和占用无冲突；原子释放配对笼 | 重放返回同一分笼事件和新占用 |
| `POST /v1/breeding-plans/{id}/start-gestation` | `post_pair -> gestation` | 至少一次已闭环 pairing_attempt，结果为有效或待定，配对笼已释放 | 重放返回同一预产区间和提醒集合 |
| `POST /v1/breeding-plans/{id}/adjust-baseline` | 状态不变；追加日期纠错事件 | 当前处于 gestation，基准来源存在，新时间合法，提醒重算预览已确认 | 重放返回同一纠错事件与 superseded/new 提醒摘要 |
| `POST /v1/breeding-plans/{id}/confirm-birth` | N>0：`gestation -> litter_nursing`；N=0：`gestation -> no_litter_outcome` | 尚无有效生产结果；时间、N、其他结果、母鼠状态合法；N>0 时母带崽笼有效；N=0 时结果原因必填 | 重放返回原分支结果；N>0 为同一 litter/pup 集合，N=0 为同一 no_litter_outcome |
| `POST /v1/litters/{id}/count-events` | 状态通常不变；追加数量事实并重算投影 | litter 有效、事件时间不早于出生、delta 与原因匹配、身份增减可对应 | 重放返回同一 count_event 和数量投影 |
| `POST /v1/litters/{id}/wean` | `litter_nursing/weaning_due -> sex_separation_due` | 当前在管身份均有断奶结果，数量闭合，去向安排可校验 | 重放返回同一断奶事件和任务变化 |
| `POST /v1/litters/{id}/sex-and-separate` | `sex_separation_due -> individualizing` | 所有在管身份均有性别结果；unknown 有独立安排；容量、异性混笼和占用校验通过 | 重放返回同一身份性别/笼位快照 |
| `POST /v1/litters/{id}/individualize` | 状态保持 individualizing；写入完整正式档案集合并标记可完成 | 服务端重算 eligible set 与 token 完全一致，覆盖键无漏项/多项，编号、数量、笼位和谱系全部通过 | 重放返回同一 N 条 hamster 与关系集合 |
| `POST /v1/breeding-plans/{id}/complete` | `individualizing -> completed` | 数量闭合、全部应管理身份已正式建档、无性别/笼位/数量/任务阻塞 | 重放返回同一完成摘要 |
| `POST /v1/shares/{id}/revoke` | `active -> revoked` | share 属于 owner、当前未撤销；事务提交后触发 CDN purge | 重放返回首次 revoked_at；公开 API 立即失效，边缘内容最迟 60 秒失效 |

## 9. 异常与离线体验

| 场景 | 产品行为 |
|---|---|
| 网络离线 | 展示最后同步时间和只读缓存；编辑可保存本地草稿，提交按钮提示联网后继续 |
| 版本冲突 | 保留本地输入，拉取最新版本并展示差异，不自动覆盖服务端 |
| 分笼未完成 | 保持 hold 和最高优先级任务，保留配对笼占用 |
| 超过预产窗口 | 生成单条滚动升级任务，提供继续观察、修正基准或确认未产 |
| 数量不闭合 | 阻止完成和归档，展示差额来源与补录入口 |
| 性别待复核 | 创建独立临时安排和复核任务 |
| 媒体失败 | 业务事实保存，媒体显示失败和重试 |
| 分享已撤销 | 公开页显示链接已失效，不泄露历史内容 |
| 导出/备份失败 | 保留任务、原因和重试入口，不影响业务数据 |
| 通知权限关闭 | 站内任务照常存在，提示本地通知未开启 |

## 10. 非功能需求

### 10.1 安全与隐私

1. 全链路 HTTPS；访问令牌安全存储。
2. owner_id 隔离必须有仓储层和接口层双重自动化测试。
3. 私有媒体使用短期签名 URL；公开媒体只通过有效 share token 暴露。
4. 验证码接口具备手机号、设备和 IP 维度的频率限制及审计。
5. 导出、备份和公开分享记录创建、下载、撤销和失败审计。

### 10.2 性能

1. 在正常 4G 网络下，常用列表首屏目标 2 秒内可交互。
2. 非媒体同步接口 p95 目标小于 800 毫秒；复杂谱系和数据中心聚合 p95 目标小于 1500 毫秒。
3. CSV 导入、导出、备份和视频转码使用异步任务，不占用同步请求直到完成。
4. 今日首页优先展示缓存骨架和最近数据，再增量刷新。

发布前性能测试使用固定基线，结果记录 p50/p95/p99、错误率、数据库 CPU/锁等待和 Outbox 积压：

| 测试面 | 固定参数 | 通过标准 |
|---|---|---|
| 账号数据量 | 单 owner 2,000 条 hamster（其中 500 active）、1,000 个 litter、200 个 enclosure、100,000 条 weight_record、20,000 条 care_task、10,000 条 media_asset 元数据 | 列表、今日、窝次和谱系测试均使用该数据集，不以空账号结果代替 |
| 同步 API 稳态 | 50 个已认证虚拟用户、30 请求/秒、持续 15 分钟；混合读取 80%、写入/动作 20% | 普通 API p95<800ms，复杂谱系/聚合 p95<1500ms，服务端 5xx<0.5%，无 owner 串读和重复动作 |
| 同步 API 突发 | 100 请求/秒、持续 60 秒；包含今日刷新、详情读取、称重和任务完成 | 错误率<1%，突发结束后 2 分钟内队列/连接池恢复，无丢失写入 |
| 移动端 4G | RTT 100ms、下行 10Mbps、上行 2Mbps、1% 丢包；冷缓存加载 50 条列表首屏 | P05/P08/P10/P13 首屏 2 秒内可交互，后续数据可增量加载 |
| CSV 预检 | 10,000 行，包含 10% 父母/窝次引用和 5% 可报告错误 | 创建任务接口 2 秒内返回 job_id；全量预检 5 分钟内完成且错误数、行号完整 |
| 结构化导出 | 100,000 条跨域记录，不含媒体二进制 | 创建任务接口 2 秒内返回；10 分钟内生成带哈希文件 |
| 基础备份 | 1GB 媒体清单规模与完整结构化数据，媒体只生成清单和校验，不在同步请求复制 | 创建任务接口 2 秒内返回；15 分钟内生成可校验备份包或明确失败原因 |
| 分享撤销 | 连续执行 100 次创建—访问—撤销，覆盖 WEB-01、公开 JSON 和媒体缓存 | 撤销后公开 API 下一请求均失效，所有边缘/媒体内容在 60 秒内失效，无白名单外字段 |

### 10.3 可靠性与审计

1. confirm-birth、separate、individualize、正式导入和分享撤销具备幂等保障。
2. 数量、状态和谱系的关键纠错保留前值、操作时间和原因。
3. Outbox 事件可重试，重复消费不得产生重复任务、计量或媒体记录。
4. 备份包包含校验哈希；损坏或不完整时不得显示为可恢复。

### 10.4 可用性与兼容

1. 支持当前主流 iOS 与 Android 版本，具体最低版本由工程初始化时锁定并写入发布说明。
2. 全量简体中文，日期和时区默认中国大陆习惯。
3. 关键状态不仅依赖颜色，同时提供文字和图标。
4. 表单错误定位到字段，批处理错误定位到具体行和具体对象。

#### AC-01 标准完整流程

给定父母档案、物种规则和可用笼盒，用户依次完成发布计划、开始配对、分笼、孕期观察、confirm-birth 原子建窝、断奶、分性分笼和个体化；系统按主状态链推进，每一步记录时间，最终数量零差额并形成父母边、窝次成员和正式个体关系。  
映射：BRD-01 至 BRD-10、LIT-01 至 LIT-12、P16 至 P24。

#### AC-02 配对异常后立即分笼

配对中选择“攻击/受伤，立即停止”后进入 hold，停止计时，生成最高优先级分笼任务；双方去向笼盒完整保存后才允许进入观察或终止。  
映射：BRD-05、BRD-06、A08、A09、P18。

#### AC-03 分笼笼位冲突

目标笼盒同时段已有占用时，系统展示冲突对象和时段，保持当前状态且不释放配对笼；更换有效笼盒后原子提交成功。  
映射：ENC-04、ENC-05、BRD-05、A09。

#### AC-04 配对结果待定

已完成分笼但未观察到明确交配时，可选择“结果待定，进入观察”；状态进入 gestation，页面显示“观察窗”而不是“确认怀孕”，并生成预产区间提醒。  
映射：BRD-07、P19。

#### AC-05 超过预产区间仍未产仔

晚于预产区间结束且无生产记录时，只生成一条滚动升级的逾期确认任务；用户可继续观察、修正基准时间或确认未产。  
映射：BRD-08、TSK-07、P07、P19。

#### AC-06 重复提交生产确认

同一计划已有有效生产结果时，再次使用相同幂等键提交，服务端返回原分支结果：N>0 返回已有 litter 和 pup_identity，N=0 返回已有 no_litter_outcome；不得创建第二套事实。  
映射：LIT-01 至 LIT-04、P20。

#### AC-07 修正实际配对时间

孕期观察中将配对基准从 T1 修正为 T2，系统追加纠错事件，重算预产区间；旧提醒 superseded，新提醒无重复，并展示提醒变更摘要。  
映射：BRD-09、TSK-06、P19。

#### AC-08 窝仔数量变化

初始活仔数为 N，后补发现 +A、死亡 -B 后，当前应管理数为 N+A-B；每次变化保留独立流水，初始事件不被覆盖。  
映射：LIT-06、LIT-07、A10、P21。

#### AC-09 性别待复核

断奶后存在 unknown 幼崽时，提交分性分笼必须为其提供独立临时安排并生成复核任务；达到规则前不得进入完成状态。  
映射：LIT-08、LIT-12、A11、P22。

#### AC-10 数量不闭合时阻止归档

当前应管理数为 8，但正式档案和未个体化身份合计为 7 时，系统展示差额 1 并保持 individualizing；补录数量事件或个体化后才可完成。  
映射：LIT-07、LIT-09 至 LIT-12、P23、P24。

#### AC-11 通知权限关闭

系统通知权限关闭后，断奶、分性和称重等站内任务仍创建并可完成；页面提示本地通知未开启。  
映射：TSK-05、P05、P06。

#### AC-12 并发操作

客户端基于旧 version 提交已被另一请求完成的分笼动作时，服务端拒绝旧版本并返回最新对象；刷新后可查看已完成操作，不产生重复事件。  
映射：BRD-10、8.1 通用 API 规则。

#### AC-13 幼崽掉重双通道预警

幼崽新体重低于上次或出生体重时，原始记录保存成功，生成一个最高优先级掉重任务和可追踪通知结果；重复采集不重复告警。MVP 至少保证站内任务和本地通知，远程通道保留数据结构。  
映射：WH-02、WH-03、WH-04、P07、A10。

#### AC-14 整窝称重任务逐只完成

关键日龄任务关联 8 条在管 pup_identity，完成 6 条时显示 6/8；最后 2 条完成后任务自动关闭，每条称重保留独立记录。  
映射：TSK-03、WH-01、A10、P21。

#### AC-15 报喜卡生成失败不影响生产确认

confirm-birth 已成功但报喜媒体生成失败时，业务结果仍完整提交：N>0 已进入 litter_nursing 并存在窝次和 N 条临时身份，N=0 已进入 no_litter_outcome 且不存在窝次；报喜卡标记待重试，重试不重复提交生产。  
映射：LIT-02 至 LIT-04、MED-05、P20、P21。

### 11.2 新增 MVP 验收案例

#### AC-16 账号 owner_id 隔离

给定账号 A 与账号 B 各有仓鼠、媒体和备份，A 使用任意 B 的资源 ID 发起读取、更新、导出或签名请求时，服务端返回统一的不可访问结果，且审计中不泄露 B 的业务字段。  
映射：ACC-03、ACC-04。

#### AC-17 CSV 全流程导入

#### AC-18 CSV 逐行错误报告

CSV 同时包含重复编号、父母缺失、循环谱系、同窝父母/出生日期冲突、核心字段覆盖、笼位冲突和非法体重时，预检展示全部问题；阻塞错误修复前不允许正式导入，报告可下载且包含行号、列名、原值和修复建议。  
映射：IMP-01、IMP-02、IMP-04、IMP-07 至 IMP-09。

#### AC-19 图片编辑与短视频失败恢复

图片编辑保存派生文件且原图保持不变；短视频转码失败时业务记录仍存在，媒体显示失败原因和重试入口，成功重试后更新为可播放。  
映射：MED-01 至 MED-05、A04、P28。

#### AC-20 可撤销公开分享

舍主只选择仓鼠昵称、主图和基础谱系创建分享；WEB-01 的 SSR 首屏只显示这些字段。舍主撤销后，公开 API 下一请求立即失效，HTML/JSON 不缓存，公开媒体和边缘缓存最迟 60 秒失效，之后再次访问不返回历史内容。  
映射：SHR-01 至 SHR-06、A12、P28、WEB-01。

#### AC-21 导出与备份

用户从数据中心创建全量导出和基础备份，任务异步显示进度；成功后可下载带校验信息的文件。任务失败时显示原因和重试，不影响业务数据。  
映射：DAT-03 至 DAT-08、P27。

#### AC-22 用量计量

创建、关闭或删除相关实体后，六项用量经幂等事件更新；P25/P27 展示当前值和更新时间。计量延迟或失败不阻止业务写入，也不出现付费墙。  
映射：USG-01 至 USG-05。

#### AC-23 数据中心显性入口

登录后进入 P25，可直接看到数据中心卡片、最近备份和用量；P05/P07 同时显示备份状态及失败入口，无需进入深层设置。  
映射：DAT-01、DAT-02。

#### AC-24 confirm-birth 两分支原子结果

输入 N=6 时，服务端一次性创建一个有效 litter、一条 delta=6 的 initial 数量事件和 6 条唯一 temporary_code 的 pup_identity，并直接返回 litter_nursing；输入 N=0 时，服务端只记录 no_litter_outcome 所需生产事实，不创建 litter、数量事件或临时身份。两种分支模拟任一步失败时数据库均不留下半成品。  
映射：LIT-01 至 LIT-04。

#### AC-25 individualize 原子转换 N 条正式个体

给定 6 条已完成断奶、分性和笼位分配的在管 pup_identity，服务端预览计算完整 eligible set 与 token；提交 individualize 时服务端重新计算并确认集合未变化，随后一次性创建 6 条 hamster、6 条正式 litter_member 和对应 pedigree_parentage，并回填一对一映射。客户端漏传、多传、集合变化或任一编号冲突时整体拒绝/回滚并返回最新逐项结果。  
映射：LIT-09 至 LIT-11、P23。

#### AC-26 离线只读缓存

设备离线时可查看最近同步的今日、仓鼠、窝次和笼盒数据，并保存表单草稿；任何状态迁移、正式导入、分享、导出或备份提交均提示联网后继续，联网恢复后由用户明确提交。  
映射：3.3 技术与运行边界、9 异常与离线体验。
