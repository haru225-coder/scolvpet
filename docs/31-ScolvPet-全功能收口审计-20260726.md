## 3. 发布层 P1/P2 声明核验：10 属实 / 2 不实

属实（摘要）：迁移 0040（部分唯一索引、票据 sha256 一次性）、三端点、wechat provider http+mock、production 强制校验（`config.go:168-177`）、SessionKey 不出 handler、IP 频控、OpenAPI+dart 客户端、小程序三态 + 隐藏验证码区块、db-verify 74 表断言、Makefile 目标与 fixture。`touristappid`/`p.scolv.com` 残留扫描：小程序侧全部在安全位置。

### ❌ 不实 1：`.env.production.example` 与 config 校验不对齐（P1-2 声明"逐项对齐"）

- `deploy/vps/.env.production.example` **完全缺失 `WECHAT_PROVIDER`**。`config.go:87` 默认 `mock`，`:168` 生产强制 `http` → **照模板部署，生产启动直接失败**。
- `WECHAT_APPID/SECRET` 为注释态，注释还写"届时并入强制校验"——校验**已经**在强制了，文案过期。
- `scripts/production-readiness-smoke.sh` 零 wechat 断言，静态断言只覆盖 SMS。

### ❌ 不实 2：`build-miniprogram.sh` fail-closed 覆盖缺项（P1-1 声明对齐任务书）

- 任务书 docs/30:50 明文要求"`MP_APPID` wx 开头长度不对"校验——**从未实现**，`MP_APPID=abc` 可通过生产门禁。
- "MP_APP_ENV != production 退出非零"实际语义相反：非 production 直接跳过全部校验放行（dev 直通本身合理，但与声明不符）。

### ⚠️ 范围外新发现：Flutter 侧 staging 默认值单路径守卫

`apps/mobile/lib/core/app_config.dart:7,12` 编译期默认 `https://p.scolv.com:8443`。守卫只在 `make release-android` 一条路径；**iOS 无对应 fail-closed 目标**，README 甚至示范裸 `flutter build ios --dart-define=...p.scolv.com`。发布 iOS 前必须补。

### ❌ P1-2 推迟项未回收：`/readyz` 生产自检

`server.go:133-139` 仍是裸 DB ping。当时推迟理由（server.go 被并行任务占用）早已解除，无人回收。smoke 脚本以"现状契约"绕过了任务书验收原意。
