# ScolvPet 小程序 B 端全量迁移任务书

**日期**:2026-07-27
**性质**:产品定位变更 + 前端平台工程。本书是「把 Flutter App(B 端经营能力)迁到微信小程序」的总纲,设计先行,分期交付。
**触发**:核心客户(熊舍主,双手机场景)明确要求以小程序为**主要管理入口**,全部经营动作在小程序内完成,前端手感须接近现有 iOS(Flutter)端。
**前置**:`docs/30` 发布层任务书照常推进(P4/P5 不被本书阻断);`CORE_CODE_FREEZE.md` 冻结域继续有效。

---

## 0. 决策记录(推翻既有定位,需留痕)

| 既有决策 | 出处 | 本书变更 |
|---|---|---|
| 小程序只做客户侧(看宝宝/预约/沟通/确认购买) | `docs/27` §8 | **反转**:小程序成为 B 端(繁育者)主要经营入口,C 端切片保留 |
| 小程序发布是沙箱状态机,App 内只读隐藏 | `docs/28` P0-7 | 不变(App 内说明页维持只读) |
| App(Flutter)是 B 端唯一全功能端 | `docs/25` / `docs/27` | App 降级为**并行端**:桌面小组件、本地通知、IAP 等平台专属能力保留在 App |

「迁移」的工程实质:**Flutter 的 Dart 代码在小程序上零复用,20+ 业务模块按小程序技术栈重写**。唯一共享真源是后端 OpenAPI 契约(`specs/api/openapi.yaml`)。

## 1. 技术路线(已定:Taro + Skyline,原生页面混写)

三条路线论证:

| 路线 | 优点 | 否决/采纳理由 |
|---|---|---|
| 继续手写原生 WXML | 与现有 7 页一致、无框架税 | **否决**:20+ 模块手写,无组件抽象,开发与维护成本不可控 |
| **Taro(React)+ Skyline** | 组件化、TS 契约客户端、可沉淀仿 iOS 组件库;Taro 支持混入原生页面,现有 C 端 7 页不必重写 | **采纳** |
| Flutter 转小程序(MPFlutter 类) | 理论复用 Dart | **否决**:成熟度不足、包体积逼近分包上限、审核风险、渲染非原生手感 |

落地形态:

- 新建 `apps/miniprogram-next`(Taro 4.x + React + TypeScript),编译目标 weapp,**Skyline 渲染引擎**(`renderer: skyline` 按页面粒度开启,worklet 动画 + 自定义路由转场 + 手势返回)。
- 现有 `apps/miniprogram` 的 C 端 7 页以**原生页面混写**方式并入 Taro 工程(Taro 支持原生页面共存),`utils/config.js` 的 fail-closed 构建注入机制原样移植到新工程;混入完成、真机回归通过后,旧目录归档删除。
- 迁移期间 C 端切片的上架(docs/30 P4/P5)**不等待**本书:若 AppID/域名先到位,以现有 `apps/miniprogram` 先行上架,B 端分期叠加发版。
- 包体策略:主包只放登录 + 今日 Tab,B 端各域走**分包**(微信单分包 2MB / 总包 30MB,须在 M0 建立分包地图并纳入 CI 体积门禁)。

## 2. 设计体系(design-first,M0 必须先锁)

目标:手感对齐 Flutter 端 `ios_theme.dart` 的 iOS HIG 体系(参照 `docs/16` 视觉收口标准)。

- **M0 交付一份《小程序仿 iOS 设计规范》**:色彩/字号/间距 token(从 `ios_theme.dart` 导出为 TS token 文件)、导航模式(自定义导航栏 + Skyline 手势返回)、列表/表单/弹层/动作面板组件清单、动效强度参数。
- 组件库 `@scolvpet/mp-ui`(工程内 package):iOS 风格 NavBar、大标题滚动收缩、SectionList、SwipeAction、Sheet/ActionPanel、SegmentedControl、日历、图表容器。**先做组件库 Gate(样例页真机过手感)再开业务页**。
- 原型:沿用 `prototype/figma-import` 的设计声明与组件板为基线,补小程序画板(缺口:现有原型只为 Flutter 五导航画)。

## 3. 平台受限能力与替代方案(产品取舍,写死在本书)

| Flutter 能力 | 小程序限制 | 替代方案 | 期次 |
|---|---|---|---|
| 付费墙 / IAP | iOS 内虚拟支付政策受限 | **不迁**。小程序端只展示权益状态,购买引导回 App/其他合规路径;政策再评估前不做小程序内购 | 不迁 |
| 本地通知(任务提醒) | 无本地通知 | **订阅消息**(服务端推,模板申请纳入外部申请清单)+ 今日 Tab 角标 | M2 |
| 合同 PDF 本地生成/打印 | 无本地 PDF 能力 | **服务端渲染 PDF 端点**(后端新增,见 §5 解冻清单),小程序侧预览/转发文件 | M3 |
| 桌面小组件 WidgetKit | 无对等能力 | 不迁,App 专属 | 不迁 |
| CSV 导入(I2Import) | 文件系统受限 | `wx.chooseMessageFile`(从聊天选文件)+ 现有导入任务端点;体验降级可接受 | M3 |
| 离线缓存与只读降级 | storage 10MB 上限 | 仅缓存今日队列 + 最近访问个体的只读快照,弱网降级提示 | M2 |
| AI 助手流式对话 | 可行(需长连接/分块) | 复用现有 assistant 契约,SSE 不可用则轮询降级 | M4 |
| 推送设置(APNs) | 不适用 | 改为订阅消息授权管理页 | M2 |

## 4. 契约与工程机制

- **TS 契约客户端**:`openapitools.json` 增 typescript 生成器,产出 `generated/ts/scolvpet-api`,Taro 侧统一经 adapter(注入 `Taro.request`、token、`Idempotency-Key`)消费。**禁止手写 fetch 封装**(现有 `utils/api.js` 仅服务混入的 C 端原生页,不再增长)。CI 增 client-drift 检查(对齐 Dart 客户端既有机制)。
- **B 端登录**:复用现有繁育者短信登录契约(Flutter LoginScreen/CodeScreen 同源);wx.login 静默登录按 docs/30 P2 的三态机制作 **B 端镜像**(openid ↔ 繁育者账号绑定,新端点,见解冻清单)。RBAC 沿用后端矩阵,前端按 `rbac.dart` 语义移植 TS 版。
- **构建与门禁**:`make release-miniprogram-next`,fail-closed 规则与现有脚本同标准(AppID 校验/https/禁 staging/禁端口),外加:分包体积门禁、Skyline 兼容声明检查。`make ci` 串入 taro build + 单测。
- **测试**:组件库快照测试 + 各域 controller 逻辑用 vitest;释放 gate 沿用「真机人工 PASS」惯例。

## 5. 后端解冻评估清单(唯一允许的核心侧改动入口)

本书原则上**只做前端**;以下三项涉及后端新增,逐项按 `CORE_CODE_FREEZE.md` 解冻条件评估后单独立项:

1. B 端 wx.login 绑定端点(镜像 P2 的 customer 机制,新表 `breeder_wechat_identity`);
2. 合同/回执**服务端 PDF 渲染**端点;
3. **订阅消息**下发通道(任务提醒/预订状态变更)。

均不触碰冻结域(预订 Golden Path、`reservation_id` 真源、public idempotency、跨客户隔离)。

## 6. 分期计划(每期独立可上线,按客户使用频率排序)

```text
M0 基建与设计(1–2 窗口):Taro 工程 + 分包地图 + TS 客户端生成 + 设计规范
   + @scolvpet/mp-ui 组件库 + 样例页真机手感 Gate + C 端 7 页混入回归
M1 每日经营核心(2–3 窗口):B 端登录、今日照护队列、任务列表/快速完成、
   个体/笼舍浏览与检索、体重/健康快录
M2 管理闭环(3–4 窗口):个体/笼舍 CRUD 与批量、移笼、窝仔看板(性别分笼/个体化)、
   繁育向导、日历聚合、订阅消息提醒、离线只读快照
M3 经营与交易(3–4 窗口):CRM 客户与交付、合同(服务端 PDF)、财务收支、
   成员与 RBAC、公开主页编辑、CSV 导入
M4 增值层(2–3 窗口):AI 助手、遗传/模拟 Hub、成长获客、Stud 配对合作、数据中心
不迁:付费墙/IAP、桌面小组件、APNs 推送(App 专属)
```

每期 Gate:CI 全绿 + 分包体积门禁 + 真机(双机)人工全链路 PASS + 客户试用确认后再开下期。

## 7. 与发布层(docs/30)的关系与外部申请增量

- P4(正式域名)/P5(Release Gate)照旧,以现有 C 端切片先行走完 RELEASE GATE;B 端各期作为后续版本迭代上架。
- **外部申请增量**(在既有 ICP/AppID/短信之上,均需用户发起):
  - 小程序类目核对:B 端经营工具可能需增补「工具/企业管理」类目;
  - 微信认证(订阅消息与部分能力的前提);
  - 订阅消息模板申请(任务提醒、预订状态)。
- 真机验收基线:客户的两台手机 + 开发者自有机型,每期 Gate 双机过。

## 8. 边界

- 不动后端冻结域;后端改动仅限 §5 清单且单独解冻立项。
- 不做:小程序内支付/内购、`getPhoneNumber` 一键手机号(维持 docs/30 边界)、Web 端改造(维持只读展示)。
- Flutter 端在迁移期内只修缺陷不加新功能(避免双端追平消耗);客户确认小程序侧稳定后再评估 App 的长期定位。

## 9. 风险与开放项

| 风险 | 缓解 |
|---|---|
| Skyline 在低端安卓机手感/兼容不达标 | M0 样例页真机 Gate 直接测客户双机;不达标页面回退 WebView 渲染 |
| B 端类目/资质审核不过 | AppID 申请时先行沟通类目;备选:企业主体认证后再提审 B 端版本 |
| 分包体积超限 | M0 建立分包地图 + CI 体积门禁,图表/大依赖按需异步分包 |
| 双端并行期功能漂移 | Flutter 冻结新功能;契约单一真源 + client-drift CI 双端同查 |
| 服务端 PDF / 订阅消息立项延迟 | M3/M2 对应功能页先出「App 内完成」占位引导,不阻断整期上线 |

开放项(需产品/用户决策,不阻塞 M0):付费权益在小程序端的展示口径;M4 各模块是否全做(可按客户反馈裁剪)。
