## 3. 任务目标

交付一个可在 iPhone 真机稳定运行、视觉语言统一、关键流程完整、静态检查与全量测试通过的 Flutter 客户端版本，并将结果记录到开发日志。

完成后应达到：

1. 用户首次打开应用时，可以自然完成登录、建舍和进入主壳。
2. 今日、仓鼠、笼舍、繁育、窝次、健康、任务、日历、数据中心和我的页面使用同一套视觉语法。
3. 遗传推算功能具备明确的输入层级、结果解释、空态、加载态、错误态和离线态。
4. 所有主要页面在浅色、深色、较大文字和小屏设备下保持可读、可点和不溢出。
5. 真机不出现白屏、同步构建期通知、无限宽按钮、缺字图标或网络地址误指向设备自身的问题。

## 4. 硬性设计约束

### 4.1 视觉系统

- 使用现有 `ScolvPalette`、`IosMetrics` 和共享组件，不在业务页面散落新的硬编码颜色、圆角和间距。
- 保持单一暖陶土品牌色。状态红、绿、橙仅表达真实语义。
- 页面背景、分组容器、列表行、按钮、输入框和底部导航的圆角规则必须一致。
- 插画只用于品牌、引导、加载和空态。数据密集页面保持原生列表和清晰层级。
- 不引入 AI 紫色、霓虹、展示型玻璃效果、过量阴影或三等分模板卡片。
- 不重绘现有品牌标识，不新增手绘 SVG 图标。优先使用 Cupertino 图标、现有位图资产和统一图标族。

### 4.2 原生交互

- 遵循 Apple HIG：触控目标不小于 44pt，导航语义清晰，破坏性操作有确认或撤销路径。
- 按压反馈只使用轻微缩放、颜色变化和必要的轻触觉反馈。
- 动画仅用于层级、反馈和状态转换，并尊重系统减少动态效果设置。
- 键盘出现时，表单、底部操作和输入栏不得被遮挡或触发布局异常。
- 读操作在离线时仍可浏览缓存；写入口要明确禁用原因，不得表现为无响应。

### 4.3 内容和状态

- 每个关键页面检查并补齐：加载、空、错误、离线、无权限、成功和部分数据状态。
- 文案使用简洁中文，不使用营销口吻、内部技术术语或含糊占位文本。
- 同一操作在导航、按钮和空态中的名称保持一致。
- 表单标签不能只依赖 placeholder；校验错误在对应字段附近显示。

### 4.4 范围边界

- 保留现有路由、主导航、业务字段、接口路径和数据语义。
- 不新增业务模块，不修改数据库模型，不扩展 OpenAPI 契约。
- API 与数据库仅做兼容性验证；如发现确实需要扩大范围，先暂停并向主代理报告。
- 不提交、不推送、不重写历史，除非主代理后续明确要求。

## 5. 执行范围与优先级

### P0：恢复验证能力与稳定性

1. 修复 `apps/mobile/build` 失效符号链接。优先恢复其目标缓存目录；如需改变仓库内链接策略，说明原因并保持可回滚。
2. 修复 Xcode 工程文件中的尾随空格。
3. 检查启动、主题初始化、首帧刷新、全局按钮约束、键盘输入栏和路由切换，避免白屏或构建期间同步通知。
4. 确保本地和真机 API 地址配置可区分，默认配置不误导真机连接 `127.0.0.1`。

### P1：关键用户路径收口

按以下顺序审计和修正：

1. 登录、验证码、首次建舍、会话恢复。
2. 今日首页和底部主导航。
3. 仓鼠列表、仓鼠详情、新增与编辑。
4. 笼舍列表、详情和分配流程。
5. 繁育向导、窝次看板、谱系和遗传推算。
6. 健康、任务、日历、称重和推送。
7. 数据中心、成员、合同、CRM、财务和我的。

每条路径检查：导航层级、返回行为、主操作可见性、信息密度、状态完整性、键盘避让、深色模式和小屏适配。

### P2：共享组件与一致性

- 将重复的标题、分组、列表行、输入、选择器、空态、错误态、加载态和底部操作收敛到现有共享组件。
- 优先删除页面局部视觉补丁，避免继续增加相似但不一致的组件。
- 检查 Cupertino 与 Material 组件混用场景，确保视觉和手势表现一致。
- 检查系统文字缩放至 1.3 倍时的标题、按钮、表单和列表行布局。

### P3：遗传模块体验

- 明确区分核心表推算与简化孟德尔模式，默认突出商家常用的核心表模式。
- 输入顺序应符合繁育决策：系列、父本、母本、目标表型、可选具体亲本。
- 结果需要显示预测依据、概率、历史样本量和重点表型机会，不把原始 JSON 或技术字段直接暴露给用户。
- 实际后代对比和历史反馈应让用户理解偏差来源，不使用误导性的确定性表达。
- 补齐无匹配表型、数据不足、接口错误、离线和空历史状态。

## 6. 执行方法

1. 先做只读审计，列出视觉债务和稳定性问题，按 P0-P3 排序。
2. 小步修改，每完成一组页面就执行格式化和相关定向测试。
3. 复用现有设计系统，只有确认缺少通用能力时才新增共享组件。
4. 不做大规模机械重写，不覆盖用户已有改动。
5. 最后执行全量验证，并检查 Git diff 是否混入构建产物、临时日志或无关文件。
